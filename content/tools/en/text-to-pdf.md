Plain text (`.txt`) is the most durable format in computing, yet it is also the least predictable on paper. Open an unformatted text file in macOS TextEdit, Windows Notepad, and a browser tab, and each viewer applies arbitrary margins, discordant fonts, awkward mid-word wraps, and raw filesystem headers across printed pages. Converting plain text into a vector PDF imposes clean typographic discipline—fixed margins, intentional line leading, predictable wrapping, and bottom pagination—while keeping every character crisp, lightweight, and searchable.

## Why Vector Core-14 Typography Outperforms Rasterized Screenshots

Many generic online converters render text onto an HTML canvas and embed giant JPEG images inside a PDF shell. That approach bloats a 4 KB note into a 2 MB file, blurs serif edges at 200% zoom, and destroys text selection (`Ctrl+F`).

This converter instead writes native ISO 32000 PDF text objects (`BT ... ET`) directly inside your browser using `jsPDF` and the **PDF Standard Type 1 Core-14 fonts**:

- **`Helvetica`**: Clean neo-grotesque sans-serif suited for operational memos, SOPs, and on-screen briefs.
- **`Times`**: Classic proportional serif optimized for long-form prose, formal letters, and printed reading comfort.
- **`Courier`**: Strict fixed-width monospace where every character occupies exactly `0.600 em` horizontally, preserving code indentation, tabular log fields, and ASCII diagrams.

Because PDF readers (Adobe Acrobat, Chrome PDFium, macOS Preview, Evince) ship with built-in metric tables for Core-14 families, no bulky TrueType font binaries need to be embedded. A ten-page meeting transcript frequently compresses down to **12–25 KB** while remaining infinitely sharp on 1200-DPI laser printers.

## Typographic Metrics: Points, Millimeters, and Line-Wrapping Math

Every line break in the generated PDF is computed deterministically from PostScript typographic units (`1 pt = 1/72 inch = 0.3527 mm`). Vertical baseline advance follows a straightforward linear spacing formula:

```text
Line Step (mm)        = (Font Size in pt × 0.3527) × Line Height Multiplier
Effective Width (mm)  = Page Width (mm) − (2 × Margin in mm)
Lines per Page        = floor((Page Height − 2 × Margin) / Line Step)
```

For example, `12 pt` text at `1.5x` line height advances `6.35 mm` per baseline, leaving generous whitespace between lines and accommodating roughly **38 lines per A4 page** with Medium (`25.4 mm`) margins. Before emitting each line into the PDF page stream, `splitTextToSize()` accumulates exact glyph advance widths against the effective printable column, breaking lines cleanly at whitespace boundaries. Whenever `cursorY + lineStep` crosses the lower margin threshold, the generator emits an optional bottom-center page stamp (`Page N` in `10 pt` muted gray), creates a fresh PDF page object, resets the Y cursor to the top margin, and continues seamlessly without clipping ascenders or descenders.

## Formatting Source Code, Logs, and Structured Plain Text

Developers routinely archive configuration files, incident timelines, and unit-test transcripts as PDFs for compliance tickets or offline postmortems. Two small pre-formatting adjustments dramatically improve code and log output:

1. **Choose `Courier` at `9–10 pt` in Landscape with `Small (12.7 mm)` Margins**: At `10 pt`, A4 or Letter Landscape accommodates roughly **125–130 fixed-width characters per line**, keeping 120-column source files and JSON logs from wrapping mid-token.
2. **Normalize Hard Tabs (`\t`) to Spaces Before Import**: PDF text streams do not enforce uniform tab-stop intervals across engines. Converting tabs to 2 or 4 spaces locally preserves exact indentation depth:

```bash
# Expand tabs to 4 spaces and strip Windows CR (\r) line endings before PDF export
expand -t 4 server_trace.log | tr -d '\r' > server_trace_clean.txt
```

## Character Encoding Edge Cases and Clean Pagination Tips

- **WinAnsiEncoding Scope**: Core-14 PDF fonts natively encode standard Western Latin characters (ISO-8859-1 / Windows-1252). Emoji, CJK ideographs, Cyrillic, or mathematical Unicode blocks outside WinAnsiEncoding may map to placeholder glyphs in pure Type 1 streams; sanitize decorative symbols or use ASCII arrows (`->`, `!=`, `<=`) for technical specs.
- **Line-Ending Consistency**: The browser `FileReader` handles Unix (`LF`) and Windows (`CRLF`) line breaks, preserving deliberate blank paragraphs (`\n\n`) as clean visual breaks between sections.
- **Avoiding Widowed Headings**: Because plain text carries no semantic heading tags, inserting an extra blank line above major section titles creates strong scannable hierarchy without requiring a word processor.
- **Offline Security for Sensitive Text**: Since text parsing and PDF binary assembly occur purely in local JavaScript memory, printing private recovery codes, legal notes, or internal runbooks to PDF never transmits a single character over the network.
